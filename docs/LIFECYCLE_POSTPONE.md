# Incident Lifecycle Revision: ACK + POSTPONE

This revision supersedes the previous Close Case lifecycle for the current project.

## Statuses

```text
OPEN
RESOLVED
```

ACK and POSTPONE are not statuses.

## OPEN

- `INITIAL` notification is sent immediately.
- `REMINDER` is sent every 1 minute while the incident remains OPEN.
- ACK does not stop reminders.
- POSTPONE can move the next reminder to `postpone_until`.
- POSTPONE never suppresses the initial notification.

## POSTPONE metadata

```text
postponed_at
postponed_by
postpone_until
postpone_remark
```

API:

```http
POST /api/v1/incidents/:incidentId/postpone
Authorization: Basic base64(<username>:<password>)
```

Request:

```json
{
  "user": {
    "id": "123456789",
    "name": "Budi Santoso",
    "username": "budi_ops"
  },
  "postponeUntil": "2026-08-16T13:30:00+07:00",
  "remark": "Menunggu maintenance selesai"
}
```

`postponed_at` is generated by the service at request time. `body.user.id` and `body.user.name` are required; `body.user.username` is optional. The user payload is accepted only after Telegram Bot Service authentication succeeds.

## Recovery during POSTPONE

POSTPONE does not affect monitoring. If Nomad reports recovery before `postpone_until`, the incident is immediately resolved:

```text
OPEN + postponed
  -> resource healthy
  -> RESOLVED
  -> RESOLVED webhook
  -> next_notification_at = NULL
```

The service does not wait for the postpone deadline.

## Nomad polling

```text
*/15 * * * * *
```

- Every 15 seconds.
- node-cron `noOverlap: true` remains enabled.
- The worker's explicit `running` guard also remains enabled.
